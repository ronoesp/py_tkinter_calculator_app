# FlatGridIndexer

（旧名: SerchingIndex2DArray）

## どのようなクラスか

フラットな1次元配列を、**行×列の格子(グリッド)として扱うためのクラス**です。

内部で保持しているデータの実体は1次元配列ですが、「1行あたりの要素数(列数)」を指定することで、`get_data(6)`のように**通し番号(index)だけで格子上の要素にアクセス**できるようにします。また、通し番号から元の行番号・列番号を逆算することもできます。

```python
flat = ["%", "CE", "C", "x", "1/X", "X2", "√", "/", "7", "8", "9", "*"]
num_columns = 4
```

上記の`flat`は、実質的に次の3行4列の格子を1次元に並べたものとして扱われます。

```
%   CE  C   x
1/X X2  √  /
7   8   9   *
```

## どのような時に使用するクラスか

このクラスが役に立つのは、**呼び出し側が最初から持っている情報が「行・列」ではなく「1つの通し番号」であるとき**です。逆に、データが最初から2次元配列(リストのリスト)として定義されていて、素直に2重ループで扱える場合には基本的に不要です。

具体的に使用を検討する場面の例:

- **外部から来る情報が最初から1次元の番号であるとき**
  キーボードのテンキー入力（0〜9）や、スクロール・ページ送りの通し番号を、そのままグリッド上のマス目に対応させたい場合
- **グリッドの行数・列数が実行時まで決まらず、変換ロジックを複数箇所で使い回したいとき**
  設定ファイルで列数を変更できるタイル状のUI（サムネイル一覧、ボードゲームのマス目など）で、「n番目のマス」というID管理を複数のメソッドから行う場合
- **範囲外チェックを含めて、通し番号⇔座標の変換窓口を1箇所に集約したいとき**

逆に、最初から2次元配列として持っているデータをただ列挙したいだけの場合（電卓アプリのボタン生成など）は、`enumerate`を使った2重ループの方がシンプルで、このクラスを経由する必要はありません。

## どのように使用するか

呼び出し側で「2次元配列」→「フラット化」→「列数を渡す」という手順を踏みます。

```python
from FlatGridIndexer import FlatGridIndexer

names_2d = [
    ["%", "CE", "C", "x"],
    ["1/X", "X2", "√", "/"],
    ["7", "8", "9", "*"],
]
num_columns = len(names_2d[0])
flat = [name for row in names_2d for name in row]   # フラット化

indexer = FlatGridIndexer()
indexer.set_list(flat, num_columns)

indexer.get_list_length()        # -> 12（要素の総数）
indexer.get_data(4)               # -> "1/X"（先頭から4番目の要素）
indexer.get_index_row(4)          # -> 1（4番目の要素がある行）
indexer.get_index_col(4)          # -> 0（4番目の要素がある列）
indexer.is_index_in_range(20)     # -> False（範囲外）
indexer.get_data(20)              # -> ""（範囲外は空文字を返す）
```

**使い方の要点**

1. 呼び出し側で「フラットな1次元配列」と「列数」を用意する
2. `set_list(flat_list, num_columns)`で両方をセットする
3. 以降は行・列を意識せず、`get_data(index)`のように通し番号だけで要素を取得できる
4. `get_index_row(index)` / `get_index_col(index)`を使えば、通し番号から元の行・列番号を逆算できる
5. 範囲外の`index`を渡した場合、例外は発生せず`get_data`は`""`、`get_index_row`/`get_index_col`は`-1`を返す

## 設計上のポイント（旧実装からの変更点）

- **クラス名を`SerchingIndex2DArray`から`FlatGridIndexer`に変更**。スペルミス(Serching → Searching)の修正に加え、「フラット配列を格子として扱い、通し番号でアクセスする」という役割が名前から分かるようにした
- **保持するデータをフラットな1次元配列に統一**。以前は2次元配列(リストのリスト)を渡し、列数を`len(list[0])`(先頭行の要素数)から推測していたが、この方式だと以下の問題があった
  - 要素が文字列の場合、文字列自体の文字数を列数と誤認し、要素の中の1文字ずつを取得してしまう(例外は出ないが結果が壊れる)
  - 要素がlen()を持たない型(数値など)の場合、その場で`TypeError`が発生する
  - 各行の要素数が異なる配列(ジャグ配列)を渡すと、全体の要素数と行変換の基準がずれる
  これらを避けるため、列数は推測せず`set_list(flat_list, num_columns)`で明示的に受け取る設計に変更した
- **`get_data()`が行・列への変換を経由せず`self.list[index]`に直接アクセス**するだけになった。フラット配列である以上、変換が不要なため
- **`get_list_length()`は`len(self.list)`をそのまま返すだけ**になり、行数(num_rows)をクラス内部で保持する必要自体がなくなった(呼び出し側でflat_listを作る際の検証用に持つ分には自由)
- 列数(`num_columns`)は`get_index_row`/`get_index_col`で行・列を逆算する時にのみ使用する

## 注意点

- 各行の要素数が異なる配列（ジャグ配列）を元にする使い方には対応していません。渡すデータは、すべての行で要素数が同じ「長方形」の格子をフラット化したものであることを前提としています。
- `set_list()`を呼ぶまでは`get_list_length()`は`0`を返します。
- 旧クラス名(`SerchingIndex2DArray`)からの破壊的変更です。他プロジェクトで利用している場合は、`set_list()`の呼び出し側(2次元配列→フラット化→列数指定)を含めて修正が必要です。
